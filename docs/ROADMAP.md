# 走马观花 · Zouma 开发顺序与验收路线

**行于途中，思入深处。** 走马观花以对话为核心，通过 AI 教学 Agent 支持跨场景持续学习。实时语音是首个重点入口，长期方向包含知识整合、持续反馈以及语音、文本、图表、数学推导与编程实践之间的连续切换。

本次先沿用旧代码，再补实时交互与状态正确性。v0.2 已有可运行实现和模拟验证路径；**P0 仍需真实模型、麦克风和语音服务端到端验收**，不得用设备朗读加文字问答代替。

## P0：剩余最短路径

1. **短课程真实语音联调。** 用户明确启用服务与费用后，配置一个文本模型和一个 Realtime 模型；使用可核对的短教材，先验证讲授、说话打断、多轮讨论、说“继续课程”和原句恢复。记录供应商/模型、浏览器、设备和网络。
2. **课程内容复核。** 检查口述自然度、关键概念覆盖、公式符号解释、目标与检查题、补充解释标识及原文定位。当前结构可验证，教学事实和内容质量不能仅靠 JSON 校验保证。
3. **真实异常恢复。** 在句中打断、快速反复打断、回答中打断、切换课程、多标签页认领、刷新、断网、语音服务失败、文本模型超时和重启后复查主线。每次都确认没有跳过未听内容，最多重播未确认的当前句。
4. **低操作负担检查。** 首次配置完成后，从上次课程的主要入口开始；不用看屏幕完成提问、追问和恢复。验证结束时可理解地说明保存到哪一句，下次继续不要求用户记忆课程位置。
5. **更新验证记录与开源交付。** 将真实结果写入 [VALIDATION](VALIDATION.md)，修复联调问题，复核干净环境启动、配置示例、密钥排除和 MIT 许可。创建远程仓库、发布或部署需按届时授权处理。

先完成上述工作，再扩大材料格式、供应商数量或 Agent 结构。Notebook 导出继续保留，但不优先占用语音连续性工作。

## P0 用户路径

| 步骤 | 通过条件 |
| --- | --- |
| 1. 导入短教材 | 来源行号/PDF 页码可对照 |
| 2. 生成结构化课程 | 由真实模型生成，口述质量和原文忠实度经人工复核 |
| 3. 开始实时讲授 | 真实语音可听；默认不自动打开麦克风或发起付费连接 |
| 4. 讲授中说话打断 | 无需先点文字输入框 |
| 5. 停止输出并进入讨论 | 保留未确认句，恢复锚点准确 |
| 6. 连续追问至少三回合 | 可围绕教材和相关延伸话题讨论，主线位置不变 |
| 7. 要求继续课程 | 语音指令由应用识别，手动恢复也可用 |
| 8. 回到正确主线 | 恢复独立锚点，必要时简短衔接 |
| 9. 检查内容连续性 | 不跳过未听句，不重复大段已确认内容 |
| 10. 关闭再打开/重启 | 课程、可靠检查点和必要讨论记录保留，重新明确开始 |
| 11. 网络或模型失败 | 已保存位置仍在，错误有明确下一步；旧回答不能拉回旧位置 |
| 12. 无语音或语音失败 | 讲稿、文字提问、手动恢复和设备朗读仍可用 |

每次测试记录实际停声延迟、说完到回答开始的延迟、恢复位置、跳课/重复/丢状态次数，以及有效学习所需点击数和看屏幕次数。事件时间戳只反映应用观测，需额外测量麦克风输入到实际停声的链路。没有实测前不设“已达到某毫秒”的结论，不以收听时长替代理解与保留。

## P1：学习者记忆与主动学习

- 将概念与学习证据建立稳定关联，保存跨会话理解记录；这不同于 P0 的课程位置保存。
- 加入费曼式口头解释、反例和推理检查，区分复述与理解；允许学习者纠正系统判断。
- 根据实际回答、小测或练习区分听过、可复述、可解释、可迁移、可独立解题；证据不足时显示“尚无证据”。
- 课后生成可回溯的知识总结，并依据已记录证据给简单复习建议。

验收侧重解释准确性、可解释的薄弱点与延迟复测；不用虚构掌握百分比。

## P2：教学策略与理论实践闭环

- 根据真实证据规划课程，选择重讲、先修、类比、反例、复习或实践。
- 将 Python 和数学推导结果反馈到学习者状态，再调整下一步教学。
- 让语音、文本、图表、数学推导与编程实践共享课程位置和讨论上下文，验证跨模态切换能否保持思考连续。
- 代码执行接隔离环境，限制网络、文件、时间与资源；当前服务端持续禁止任意代码执行。
- 根据需要添加更多文本/Realtime/STT/TTS 适配器，比较延迟、费用和教学质量。
- 依据真实行走与通勤试用改进移动端、后台与锁屏体验；“行走帮助思考”作为待验证假设。
- 通过前后测、知识保留、迁移与独立解题评估效果，操作负担和持续使用价值共同参与判断。

每项扩展都应说明如何降低启动负担、支持主动思考、保证课程连续性或改善长期学习效果；出现具体需求前不加入复杂基础设施。
